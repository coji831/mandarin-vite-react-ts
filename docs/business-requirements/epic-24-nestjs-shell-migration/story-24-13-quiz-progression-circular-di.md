# Story 24.13: Quiz + Progression Port (Circular-DI Resolution)

## Description

**As a** backend engineer,
**I want to** port the `quiz` module — **8 routes** (7 on `QuizNestController` — `GET /v1/quiz/config`, `GET /v1/quiz/questions`, `POST /v1/quiz/attempts`, `POST /v1/quiz/attempts/:id/answers`, `PUT /v1/quiz/attempts/:id/complete`, `GET /v1/quiz/attempts`, `POST /v1/quiz/feedback` — + `GET /v1/quiz/sandhi-drill/questions` on `SandhiDrillNestController`) with the **5-strategy registry** (`audio-to-pinyin-tone`, `ime-simulator`, `radical-gate`, `comprehension`, `qualification`) + `SandhiDrillService`, and the `progression` module (**7 routes** — `GET`/`PUT /v1/progression/foundation-progress(/…/:sectionId)`, `GET`/`PUT /v1/progression/phase-gate`, `GET /v1/progression/gates`, `GET`/`PUT /v1/progression/radical-progress(/…/:radicalId)`) — from Express (`api/QuizController.ts`/`quizRoutes.ts`/`aiFeedbackRoutes.ts`/`SandhiDrillController.ts` + `api/ProgressionController.ts`/`progressionRoutes.ts`) to the NestJS 11 shell under `modules/quiz/nest/` and `modules/progression/nest/`, resolving the `progression ↔ quiz` circular dependency with a recorded ADR (`forwardRef` primary → the re-injection bridge fallback), porting the backend engine **correctly** (no backend bug canonized), unifying the `/gates` guest branch to the calibrated gate (24-7 identity / 24-5 F6), and applying the calibrated `OptionalAuthGuard` on the guest quiz submit surface,
**So that** the practice + progression surfaces become contract-identical on the Nest shell with the correct engine shape and the calibrated guest semantics — the backend half of epic-26's quiz scope lands correctly while the FE quiz-engine fixes stay in epic-26 (C-declared) — all proven by a dedicated parity harness (real Express vs real Nest) that keeps the migration additive with the Express production path untouched until the 24-15 cutover.

## Business Value

This story ports the **two collision-core modules of the migration's final port batch**: `quiz` (the 8-route practice surface with the 5-strategy backend engine + SandhiDrill + AI-feedback) and `progression` (the 7-route phase-gate / foundation / radical-progress surface). It is the **first (and only) port that must resolve a circular module dependency** — `QuizService` → `ProgressionService` (`completeQuizAttempt` → `progressionService.updatePhaseGate`) and `ProgressionService` → `QuizService` (`checkPhase3To4Gate` → `quizService.getComprehensionQuizResult`) — the highest-risk DI item the shell has faced, already registered as the epic's **R6/High `forwardRef` vs re-injection** risk. The story ships the resolution with a **recorded ADR** (the parity harness is the arbiter: `forwardRef`-direct was PRIMARY and failed it, so the as-built fallback — a construction-order break + a one-shot `onModuleInit` re-injection bridge — is documented and enforced), so the decision is auditable, not incidental.

The story also lands the last **calibrated guest-semantics surfaces** on the shell: the entire guest quiz **submit** surface (`config`, `questions`, `attempts` POST, `attempts/:id/answers`, `attempts/:id/complete`) is mounted with the calibrated `OptionalAuthGuard` (24-5) — a guest proceeds with `req.userId` **undefined** and gets **session-local mock shapes** (no persistence, no tracking — F6: guest → session-local/empty, never another user's rows, never all-unlocked), while `GET /v1/quiz/attempts` and `POST /v1/quiz/feedback` stay `RequireAuthGuard` (guests never read persisted attempts nor incur AI/vendor-cost generation). The progression **`/gates` guest branch is CALIBRATED** — the **24-7 deferred item**: the Express `getGates` guest branch still returns the F6-inconsistent **all-passed `GUEST`** object; the Nest port returns the **Phase-1-only** shape (agreeing with `createGuestPhaseGate()` → `currentPhase: 1, isGuest: true`), a documented, intentional deviation unified on Express at the 24-15 cutover.

Finally, the story makes the **C-declaration of the quiz-FE fixes explicit and safe**: the backend engine shape is ported **correctly** — `strategies/registry.ts` and `SandhiDrillService` are reused unchanged (no backend-detectable bug canonized; the known FE quiz-engine bugs — `PHASE_CONFIGS[3]` missing, key-4 duplicate, `useQuizCard` aggregation, `QuizCard` label — are **frontend-only**, live today, and stay in epic-26). The parity harness is **backend-to-backend** (Nest ↔ Express), so the FE bugs are never silently shipped as fixed. A dedicated DB-backed parity harness (`quiz-progression-parity.test.ts`, **28 tests**) boots the real Express app + real Nest `AppModule` — proving 2xx deep-equal (with the quiz question `id`/`category` shuffle-position normalization), 4xx/5xx envelope parity, guest vs registered parity, authed shared-attempt deep-equal, and the calibrated `/gates` guest shape — while the Express production surface stays untouched (dual-mode) until 24-15.

## Acceptance Criteria

- [x] **Circular-DI resolved with a recorded ADR (no mutable setter unless documented fallback)** — the `progression ↔ quiz` cycle is broken by construction-order decoupling: `ProgressionModule` builds `ProgressionService` **without** `quizService` (optional ctor param); `QuizModule` builds `QuizService` **with** `forwardRef(() => ProgressionService)` (always resolved first); **`ProgressionQuizBridge.onModuleInit`** re-injects `quizService` into the built `ProgressionService` via `ModuleRef.get(QuizService)` + the `setQuizService()` setter — invoked **exactly once at composition** (boot), never per-request. Module-level `forwardRef` is kept on both sides (`ProgressionModule` ↔ `QuizModule`) for the DI graph. The full ADR (why `forwardRef`-direct failed the parity harness — `resolveParamToken` returning `undefined` for an un-instantiated forward-ref wrapper → `checkPhase3To4Gate` returned `DEPENDENCY_MISSING` — and the fallback) is documented in `progression-quiz-bridge.ts` + both module docstrings.

## Business Rules

1. **Routes are verbatim from `ROUTE_PATTERNS`** — the quiz paths are `ROUTE_PATTERNS.quizConfig`/`quizQuestions`/`quizAttempts`/`quizAttemptAnswer(id)`/`quizAttemptComplete(id)`/`quizFeedback`/`quizSandhiDrill`; the progression paths are `ROUTE_PATTERNS.progressionFoundationProgress`/`progressionFoundationProgressSection(sectionId)`/`progressionPhaseGate`/`progressionGates`/`progressionRadicalProgress`/`progressionRadicalProgressById(radicalId)`; `/api` prefix applied by the shell. The Nest controllers mirror the Express controllers 1:1, reusing the framework-agnostic services unchanged (no re-write of the quiz engine / progression internals).
2. **Circular-DI resolution is the ADR'd fallback (as-built)** — `forwardRef`-direct was PRIMARY and **failed the parity harness**: with two `useFactory` providers each `forwardRef`-ing the other in a true cycle, Nest's `resolveParamToken` unwraps the `forwardRef` and returns `undefined` for the un-instantiated peer wrapper → whichever service constructed first got `undefined` for its peer → `ProgressionService.checkPhase3To4Gate` returned `DEPENDENCY_MISSING`. The as-built fallback breaks the construction cycle (no factory waits on the other) and re-injects via the `ProgressionQuizBridge.onModuleInit` one-shot (`ModuleRef.get(QuizService)` → `setQuizService()`, called exactly once at composition — the documented fallback per the AC). Module-level `forwardRef` is kept on both sides for the DI graph. See `progression-quiz-bridge.ts` for the full ADR.
3. **Backend engine ported AS-IS (no backend bug canonized)** — `strategies/registry.ts` + `SandhiDrillService` (incl. the 5–25 count clamp) are reused unchanged; the known quiz-engine bugs are FE-only (`PHASE_CONFIGS[3]`, key-4 dup, `useQuizCard`, `QuizCard`) and stay in epic-26 (C) — never silently shipped as fixed; the release checklist (24-14) declares them known-post-release.
4. **Calibrated auth per route** — quiz: the guest **submit** surface (`config`, `questions`, `attempts` POST, `answers`, `complete`) → **`OptionalAuthGuard`** (guest → session-local mock shapes, no persistence/tracking, never 401); `GET /v1/quiz/attempts` + `POST /v1/quiz/feedback` → **`RequireAuthGuard`** (guest → 401 `AUTH_REQUIRED`); sandhi-drill → `OptionalAuthGuard`. Progression: the read routes (`foundation-progress` GET, `phase-gate` GET, `gates` GET, `radical-progress` GET) → `OptionalAuthGuard` (guest → `[]`/calibrated gate/Phase-1-only); the write routes (`foundation-progress/:sectionId` PUT, `phase-gate` PUT, `radical-progress/:radicalId` PUT) → `RequireAuthGuard` (guest → 401 `AUTH_REQUIRED`). The `if (!userId)` branches on the user-scoped routes are defense-in-depth mirroring the Express controller structure (unreachable under the guard).
5. **`/gates` guest branch calibrated (24-7 deferred item)** — the Nest `getGates` guest branch returns the **Phase-1-only** shape (never the all-passed `GUEST` object the Express controller still returns), so `getGates` **agrees with** `getPhaseGate` (`createGuestPhaseGate()` → `currentPhase: 1, isGuest: true`) for the same guest identity — a documented, intentional deviation from Express (F6 port target); the Express controller is untouched until the 24-15 unification.
6. **`@HttpCode` status parity + the sandhi clamp** — `@HttpCode(201)` on `createQuizAttempt` (Express `res.status(201)`), `@HttpCode(200)` on `submitAnswer` + `generateFeedback` (Nest's POST default is 201 — Express returns 200), `@HttpCode(200)` implicit on `completeQuizAttempt` (PUT default 200, matches Express); `SandhiDrillService.generateQuestions` clamps `count` to **5–25** (`Math.max(5, Math.min(25, count))`) exactly like Express; `GET /v1/quiz/sandhi-drill/questions?count<1`/non-numeric → 400 `VALIDATION_ERROR` (no service call).
7. **Quiz AI-feedback rate-limit (10/min/IP)** — `QUIZ_FEEDBACK_LIMITER_CONFIG` (`windowMs: 60s`, `max: 10`, message `{ error: "Too many feedback requests.", code: "RATE_LIMIT" }`) declared in `rate-limit.config.ts` + `rateLimitQuizFeedback` mounted path-scoped on `/api/v1/quiz/feedback` in `configure-app.ts` — 1:1 with the inline `feedbackLimiter` in `api/aiFeedbackRoutes.ts` (default IP key + `{ error, code }` body).
8. **Additive-only** — the Express quiz/progression wiring (`container.ts`, `api/QuizController.ts`, `api/SandhiDrillController.ts`, `api/quizRoutes.ts`, `api/aiFeedbackRoutes.ts`, `api/ProgressionController.ts`, `api/progressionRoutes.ts`) is untouched; the Nest surface coexists until the module cutover (24-15). No `packages/shared-constants` / `packages/shared-types` / FE change. `check:module-boundaries` stays green.
