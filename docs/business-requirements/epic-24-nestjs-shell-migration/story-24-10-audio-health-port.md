# Story 24.10: Audio + Health Port

## Description

**As a** backend engineer,
**I want to** port the `audio` module — **`POST /v1/tts`**, the `AudioService` facade over `AudioSynthesizer`/`AudioPathCache`/`AudioUrlSigner` exposed through the Express `AudioController` — and the `health` module — **`GET /v1/health`**, the `HealthController` that consumes the audio facade's `healthCheck()`, **resolving the direct `modules/audio` cross-module import via Nest DI** — from Express (`AudioController.ts`/`audioRoutes.ts` + `HealthController.ts`/`healthRoutes.ts`) to the NestJS 11 shell under `modules/<name>/nest/`,
**So that** the TTS + health surfaces become contract-identical on the Nest shell with the **post-calibration** `optionalAuth` semantics absorbed from epic-25 **F5** (**cache-first-free-for-guests**: a guest cache HIT returns the signed URL with `{ cached: true }` and NO billable Google TTS generation, and a guest is never 401'd), the health module's direct `modules/audio/index.js` barrel import (the only such cross-module import in the Express wiring) is replaced by clean module-to-module Nest injection (no direct cross-module import in Nest land), and audio URL-signing/path-cache behavior stays byte-identical — all proven by a dedicated mocked-GCS parity harness (real Express vs real Nest) that keeps the migration additive with the Express production path untouched until the 24-15 cutover.

## Business Value

The audio + health port is the **first dependency-carrying port after the zero-dep pair** (24-9) — audio is a `SharedModule` consumer (the `CacheService`/`GCSClient`/`GoogleTTSClient` providers from 24-4) with the calibrated `OptionalAuthGuard` (24-5), so it de-risks the DI-and-guards pattern for the remaining ports, most immediately **24-12 readers** (whose `ReadersAudioService` will consume Nest-injected audio for passage-audio with the same calibrated F5 semantics). Health is the cheapest port **and** the one that carries the only direct cross-module import in the Express wiring — `modules/health/container.ts` imports `AudioServiceLike` straight from `../../modules/audio/index.js`. Porting health first with the cross-module import **resolved via Nest DI** (module-to-module: `HealthModule` imports `AudioModule`) is a small but structural win — it proves the shell has no need for cross-module barrel imports, the pattern readers and every later audio consumer will rely on.

The story also lands the **calibrated epic-25 F5 TTS surface**: guests get **cache-first free reads** — a GCS cache HIT returns the signed URL with `{ cached: true }` and no billable Google TTS generation (`synthesizeSpeech` not called), and a guest (no/bad token) is **never 401'd** (`OptionalAuthGuard` leaves `req.userId` undefined, matching the Express `optionalAuth` mount). This is the single-touch win of absorbing F5 into the port: the calibrated shape ships once, directly, instead of "port pre-25 then rework". Guest-visible generation on a cache MISS keeps the verbatim route behavior today, with the generated-audio path counter-gated and its mechanics deferred to epic-29 (no counter ships in this story). A dedicated parity harness (`audio-health-parity.test.ts`, 11 tests) module-mocks every external client (`GCSClient`/`GoogleTTSClient`/`GeminiService`) so both apps construct the same deterministic fakes and the suite is hermetic — proving 2xx deep-equal, 4xx/5xx envelope parity, and the F5 "cache-first-free-for-guests" contract without hitting real Google services.

## Acceptance Criteria

- [x] **TTS route ported with the post-calibration `optionalAuth` (F5)** — `POST /v1/tts` ported under `apps/backend/src/modules/audio/nest/` (`audio-nest.controller.ts` + `audio.module.ts`) as a **verbatim mirror** of the Express `api/AudioController.ts` (`{ text, voice = audioConfig.voiceDefault }` → `AudioService.getTtsUrl` → 200 `{ audioUrl, cached }`), with `@HttpCode(200)` (fixing Nest's POST default 201) and `@UseGuards(OptionalAuthGuard)` — **guest (no/bad token) → `req.userId` undefined, never 401** (F6 bad-token-as-guest proven in the harness); registered → authenticated; 400 `VALIDATION_ERROR` / 500 `TTS_ERROR` envelope parity via the 24-3 `AppExceptionFilter` (path + verb verbatim from `ROUTE_PATTERNS.ttsAudio`, `/api` prefix applied by the shell).
- [x] **Health ported using Nest-provided `AudioServiceLike` (no direct cross-module import in Nest land)** — `GET /v1/health` ported under `apps/backend/src/modules/health/nest/`; `HealthModule` imports `AudioModule` (which **exports `AudioService`**) and `HealthNestController` injects it via `@Inject(AudioService)`, with the constructor param **typed structurally** `{ healthCheck(): Promise<boolean> }` — so **no `modules/audio/index.js` barrel import exists anywhere in Nest land** (the Express `health/container.ts` keeps its direct import as the production surface until 24-15).
- [x] **Health 200 shape identical** — the full-`@Res()` mirror returns the byte-for-byte 200 shape `{ status, timestamp, uptime, services: { gemini, tts }, cache: { redis: { connected } } }` (Redis via the raw ioredis client ping, `NO_REDIS` fallback = healthy, exactly like Express) and the same 500 branch `{ error, code: "HEALTH_CHECK_FAILED", message }` written directly (never re-wrapped into the 24-3 `{ code, message, requestId }` envelope, which is not what the Express health endpoint emits).
- [x] **Audio URL-signing + path-cache behavior identical (mocked-GCS integration test)** — the parity harness (`tests/integration/nest/audio-health-parity.test.ts`, 11 tests) module-mocks `GCSClient`/`GoogleTTSClient`/`GeminiService` with shared `vi.fn()`s (so both the Express `app/container.ts` and the Nest `SharedModule` construct the same deterministic fakes) and proves 2xx status+body deep-equal and 4xx/5xx status + full `{ code, message, requestId }` envelope parity on both apps: guest cache HIT/MISS, registered cache HIT, invalid-token-as-guest, empty/pinyin/too-many-words 400s, upstream-TTS 500, GCS-signing 500.
- [x] **Cache-first-free-for-guests (F5) verified in-port** — the harness asserts a guest cache HIT returns 200 `{ audioUrl, cached: true }` and `synthesizeSpeech` is **NOT** called (no billable generation); a guest cache MISS returns 200 `{ cached: false }` (verbatim behavior today); guest-visible generation stays **counter-gated** with mechanics deferred to epic-29 (no counter ships here); **no 25–28 zone touched** (no FE / `packages/shared-constants` / `packages/shared-types` / Express route/controller file changed).

## Business Rules

1. **Routes are verbatim from `ROUTE_PATTERNS`** — `ttsAudio` (`/v1/tts`, POST) and `health` (`/v1/health`, GET), `/api` prefix applied by the shell; the Nest controllers mirror the Express controllers 1:1, reusing the framework-agnostic `AudioService` facade unchanged (no re-write of the synthesizer/path-cache/url-signer internals).
2. **TTS route verbatim** — `AudioNestController` mirrors `AudioController.ts` 1:1: the same `{ text, voice = voiceDefault }` body read (`body ?? {}` guards the no-body edge so a missing body degrades to the service's clean 400 `VALIDATION_ERROR`, never a 500), the same `AudioService.getTtsUrl(text, voice)` delegation, and the same 2xx `{ audioUrl, cached }`. Service errors propagate unchanged (`validationError` → 400 `VALIDATION_ERROR`, `ttsError` → 500 `TTS_ERROR`) — no re-classification in the controller (avoids drift with Express).
3. **Calibrated `optionalAuth` (F5/F6)** — `@UseGuards(OptionalAuthGuard)` mirrors the Express `optionalAuth` mount: guest (no/bad token) → `req.userId` stays undefined and the request **never 401s**; registered (valid token) → `req.userId` attached. The controller does **not** branch on `req.userId` (the route is verbatim); `req.userId` is read to surface the calibrated guest-vs-user distinction that epic-29's counter-gating will consume.
4. **F5 cache-first-free-for-guests** — a guest cache HIT returns the signed URL with `{ cached: true }` and no billable Google TTS generation (verified in-port: the harness asserts `synthesizeSpeech` is not called); guest-visible generation on a cache MISS keeps the verbatim behavior today, with the generated-audio path **counter-gated** and mechanics deferred to epic-29 (no counter ships here).
5. **`@HttpCode(200)` parity fix** — Nest's POST default status is 201; the Express controller calls `res.status(200).json(...)`, so the handler pins `@HttpCode(200)` to keep status parity.
6. **Health full `@Res()` mirror** — the success body is written with `res.status(200).json(...)` and the catch branch writes the Express `{ error, code, message }` shape directly; Nest's exception filter would otherwise re-wrap the 500 into the `{ code, message, requestId }` envelope, which is NOT what the Express health endpoint emits.
7. **Cross-module import resolved via Nest DI** — `HealthModule` imports `AudioModule` (module-to-module injection of the exported `AudioService` via `@Inject(AudioService)`) instead of the Express `health/container.ts`'s direct `../../modules/audio/index.js` import; the constructor param is typed structurally `{ healthCheck(): Promise<boolean> }` so even the type import never crosses the audio barrel in Nest land.
8. **Additive-only** — the Express audio/health wiring is untouched; the Nest surface coexists until the module cutover (24-15). No `packages/shared-constants` / `packages/shared-types` / FE change.
