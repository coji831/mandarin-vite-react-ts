# Story 24.17: Deployment Setup (PR Env Scope) + Env-Isolation Hardening + IaC

## Description

**As a** release captain / backend operator,
**I want to** (1) **deploy to production** — push → merge the PR (the **two-fold merge gate** = `preview.yml` smoke green + the **R1/R2 env-isolation upserts verified**) → Railway prod deploy → post-flip prod smoke + T+0→24h watch window (the **T+0 rollback-decision point**: owner judgment → redeploy the previous Railway release or `git revert`, per `deployment.md` §Rollback), (2) **harden env isolation** — R1 (per-env JWT secrets + `JwtService` env claim + prod rotation at T+0), R2 (the `HEALTH_PROBE_EXTERNAL=false` probe gate — Gemini/TTS health checks short-circuit — + per-env GCP → preview SA `preview-service` + sandbox bucket `pinyin-pal-preview-data`), R3 (Neon `parent_branch: demo` preview branch, non-blocking), R6 (backup gate, doc-only), with R4/R5 deferred to Phase-2, (3) **land the IaC** — `terraform/README.md` + the additive preview SA + sandbox bucket, plus the committed `docs/guides/operations/env-isolation.md` extraction and the NestJS refresh of the IaC runbook + deployment guide, (4) keep **post-merge bugs → hotfix on main** (a separate concern, NOT in 24-17), and (5) record the **owner external validations** (incl. the new upsert/secret/demo checks),
**So that** the NestJS production release ships with per-environment isolation (a preview deployment can no longer mint prod-valid JWT tokens or touch prod GCS), verifies, and rolls back safely — rollback is the single-page note in `deployment.md` §Rollback (redeploy-previous + `git revert`, no rehearsal), "PR green" means behavioral smoke green + isolated secrets + verified upserts, and post-merge bugs are handled as hotfixes on main.

The core value is unchanged — **the Epic 24 NestJS production release ships, verifies, and rolls back safely** — and 24-17 now additionally hardens the environment boundaries that the PR-env smoke surface depends on, so "PR green" is evidence of an actually-isolated, behaviorally-correct release candidate. The smoke asserts the real behavior a failed release would break (auth, guest phase-gate shape, 4xx envelope), and the R1/R2 upserts prove the PR env is secret-isolated before it merges. The **merge gate is two-fold**: `preview.yml` smoke green (machine) + the R1/R2 upserts verified (human) — the rehearsal leg was dropped. The post-flip prod smoke + T+0→24h watch remains the **T+0 rollback-decision point** (owner judgment → redeploy-previous or `git revert`, per `deployment.md` §Rollback). Post-merge bugs are **NOT in 24-17 scope** — any defect surfaced by the post-flip smoke/watch goes to the **hotfix-on-main** path (a separate concern handled after the release).

## Business Rules

1. **Deployment is the core of 24-17** — push → merge PR (the **two-fold merge gate**: smoke green + R1/R2 upserts verified) → Railway prod deploy → post-flip prod smoke + T+0→24h watch (the **T+0 rollback-decision point**). The deployment enablers (rollback note, PR-env smoke, config normalizations) are deployment prep, not a general infra-setup bucket.
2. **Rollback is the single-page note** (`deployment.md` §Rollback) — primary = redeploy the previous Railway release (Railway dashboard → Deployments); fallback = `git revert <bad-commit>` on `main` → push → Railway redeploys. The former two-layer pinned-tag model + runbook are retired (the tag points at a pre-24-17 tree lacking the R1 env claim + R2 probe gate — rolling back to it would re-open the isolation holes). No rehearsal, no trigger table, no pinned tag.
3. **Post-flip watch cadence T+0..24h** (owner-approved timebox) — T+0 merge; T+5–15min post-flip smoke → No-Go #1; T+15–60min log scan → No-Go #2; T+1h–24h watch; clean → declare stable, unblock epics 25–28. The post-flip prod smoke + T+0→24h watch is the **T+0 rollback-decision point** — a red prod smoke is triaged as env-diff (fix env, redeploy — no rollback) vs code-regression (revert per `deployment.md` §Rollback), diffing against the green PR smoke.
4. **Env-isolation placement (approved final plan)** — **R1 + R2 land in 24-17** (code deltas: `JwtService` env claim + probe gate + tests; CI upserts: `preview.yml`); **R3 non-blocking** (Neon `parent_branch: demo` — owner action; fallback if not ready); **R4/R5 deferred to Phase-2** (CORS wildcard origins + shared Redis keyspace — documented in `env-isolation.md`, not implemented); **R6 doc-only** (backup gate in `deployment.md`; Neon backup console-side, not automated).
5. **Per-env isolation is a merge-gate input, not optional** — the merge PR must show the R1/R2 upserts live (per-env JWT + probe gate + preview SA/sandbox) before it merges; a preview env that can mint prod-valid tokens or touch prod GCS is a failed gate.
6. **Post-merge bugs → hotfix on main (NOT in 24-17)** — any defect surfaced by the post-flip smoke/watch is handled as a hotfix on `main` (a separate concern, not part of this story). 24-17 ships and verifies the release; it does not carry a production-bugfix contingency.
7. **IaC is additive-only** — the preview SA + sandbox bucket are new Terraform resources that do not modify existing resources; `terraform-apply.yml` auto-runs on `main` post-merge, so the **manual branch apply happens BEFORE the release PR** (owner runs `terraform apply` on the branch + stores `GCP_PREVIEW_SA_KEY` as a GitHub secret — C2b live for the release PR).
8. **No dedicated staging environment** — the PR env IS the smoke + isolation-verification surface (build/migrate/boot fidelity matches prod; shared Gemini/TTS/GCS/Redis instances are consumed read-only where possible). The migration set is additive-only and is **never rolled back** (no DDL needed).
9. **Sequencing** — 24-17 (deployment setup — PR env scope) runs AFTER **24-16 (docs)**, the FIRST pre-merge commit group; both land before the single merge. 24-16 references this story's artifacts as forward-pointers ("delivered in 24-17").
