# Story 24.8: Characters + Mnemonics Port

## Description

**As a** backend engineer,
**I want to** port the `characters` module — **two controllers** (`CharactersController` + `PinyinController`), **7 routes**: `GET /v1/characters/:glyph`, `GET /v1/characters/:glyph/phonetic`, `GET /v1/characters/:glyph/homophones`, `GET /v1/characters/:glyph/decomposition`, `GET /v1/characters/search`, `GET /v1/characters/frequency` + `GET /v1/pinyin/search` (deep-param routing + `/search`) — and the `mnemonics` module — **4 routes**: `GET/POST/PUT/DELETE /v1/mnemonics/:character`, cache + gemini + `optionalAuth` — from Express (`CharactersController.ts`/`PinyinController.ts`/`charactersRoutes.ts`/`pinyinRoutes.ts` + `MnemonicsController.ts`/`mnemonicsRoutes.ts`) to the NestJS 11 shell under `modules/<name>/nest/`,
**So that** the characters + mnemonics surfaces become contract-identical on the Nest shell — **the first module port to consume the shared cache/gemini infra (`SharedModule`, 24-4) and the calibrated `OptionalAuthGuard` (24-5)** — proven by a dedicated DB-gated parity harness (real Express vs real Nest) that keeps the migration additive with the Express production path untouched until the 24-15 cutover.

## Business Value

The characters + mnemonics port is the mid-migration batch's first **dependency-carrying** port. Characters are public static reference data (7 routes, two controllers — deep-param routing under `:glyph` plus the `/search` surface), the cheapest and safest proof that a multi-controller Nest module composes correctly. Mnemonics is the real de-risker: it is the **first consumer** of the shared infra (`SharedModule`'s `CacheService` + `GeminiService` from 24-4) and of the **calibrated `OptionalAuthGuard`** from 24-5 — the first module to prove that a guest (no token) proceeds with `req.userId` **undefined** on a read route, skips the user-edited branch of the 4-step lookup chain, and never sees another user's edited story (never 401 on GET, never all-unlocked — F6 calibrated semantics), while the write surface (`POST`/`PUT`/`DELETE`) is `RequireAuthGuard`-gated (guest → 401 `AUTH_REQUIRED`), and the per-method rate limiters (GET 60 / POST 10 / PUT 30 / DELETE 30 per minute) match `mnemonicsRoutes.ts` 1:1. A dedicated DB-gated parity harness (`characters-mnemonics-parity.test.ts`) proves 2xx body/status parity (deep-equal on deterministic paths — pictograph fixtures short-circuit Gemini so no real AI is hit) and 4xx envelope parity (`code`/`message` byte-for-byte equal to the Express legacy bodies), so the AI-generation cost surface and the guest-read semantics are verified without hitting vendor APIs. This de-risks the remaining dependency-carrying ports (24-10 audio, 24-11 review, 24-12 readers, 24-13 quiz/progression) that consume the same shared infra + calibrated guards.

## Business Rules

1. **Routes are verbatim from `ROUTE_PATTERNS`** — `charactersByGlyph`/`charactersPhonetic`/`charactersHomophones`/`charactersDecomposition`/`charactersSearch`/`charactersFrequency`/`pinyinSearch`/`mnemonicsByChar` (`/v1/characters/*`, `/v1/pinyin/*`, `/v1/mnemonics/*`, `/api` prefix applied by the shell); the Nest controllers mirror the Express controllers 1:1, reusing the framework-agnostic services unchanged.
2. **Envelope parity (24-3 contract)** — 4xx/5xx are thrown as `HttpException`s carrying the same `code` + `message` as the Express legacy `{error, code}` / `{error, code, message}` bodies; the global `AppExceptionFilter` serializes them into `{code, message, requestId}`. `code`/`message` are byte-for-byte equal to Express; the legacy `error` key is superseded by the envelope.
3. **Characters are public static reference data** — no auth, no cache, no external clients; the repos self-import the shared Prisma singleton (matching the `words` port in 24-2), so `characters.module.ts` needs no `SharedModule`.
4. **Route-shadowing parity is preserved** — `:glyph` is declared FIRST exactly as in `charactersRoutes.ts`, so `GET /v1/characters/search` + `/frequency` are matched by the `:glyph` handler on BOTH apps (400 `VALIDATION_ERROR` "Invalid character glyph"). This is a **pre-existing latent Express behavior** (no frontend consumer calls those two paths today; the underlying 2xx search/frequency logic is covered by `CharactersService` unit tests) and is reproduced byte-for-byte so the parity harness stays green. `pinyinRoutes.ts` registers only `/search` (no `:glyph` sibling), so `GET /v1/pinyin/search` is NOT shadowed.
5. **Mnemonics guard mapping verbatim from `mnemonicsRoutes.ts`** — `GET /v1/mnemonics/:character` → calibrated `OptionalAuthGuard` (guest → `req.userId` undefined → empty, never another user's rows); `POST`/`PUT`/`DELETE` → `RequireAuthGuard` (guest → 401 `AUTH_REQUIRED`, before the controller's own defense-in-depth `!userId` → 401 `AUTH_ERROR` check, which is kept to mirror the Express controller structure).
6. **Per-method rate limiters are 1:1 with `mnemonicsRoutes.ts`** — GET 60 / POST (generate) 10 / PUT (update) 30 / DELETE (reset) 30 per minute, mounted path-scoped at `/api/v1/mnemonics`; the 429 body (express-rate-limit default handler sending the `message` object directly) is byte-identical to Express — no envelope.
7. **Additive-only** — the Express characters/mnemonics wiring is untouched; the Nest surface coexists until the module cutover (24-15). No `packages/shared-constants` / `packages/shared-types` / FE change.
