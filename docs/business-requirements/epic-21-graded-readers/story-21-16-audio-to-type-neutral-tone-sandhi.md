# Story 21.16: Audio-to-Type Neutral Tone & Sandhi Extension

**Last Update:** July 30, 2026

## Description

**As a** learner,
**I want to** practice distinguishing neutral tone (tone 5) from full tones and receive sandhi-aware scoring in the Audio-to-Type quiz,
**So that** I can recognize toneless syllables and tone sandhi patterns in natural speech.

## Business Value

Extend the Audio-to-Type phase gate quiz (Phase 1 foundations gate) with neutral tone (tone 5) support and sandhi-aware scoring. The quiz follows the strategy pattern in `features/quiz/` and generates questions via the backend `AudioToPinyinAndToneStrategy`. This enhancement aligns the Phase 1 gate quiz with the Mandarin fundamentals curriculum — neutral tone (轻声, ~15% of common words) and 3-3 tone sandhi (3rd+3rd → 2nd+3rd) are core phonological patterns that learners must practice from the start.

Currently the quiz only tests tones 1–4, ignoring the critical neutral tone (轻声/qīngshēng) that appears in ~15% of common Chinese words (particles like 吗, 了, 的, suffixes like 们, 子). Additionally, the quiz does not account for tone sandhi — a learner who types the dictionary tone instead of the spoken tone is marked wrong even though they know the correct underlying tone. This story extends the quiz with neutral tone support and sandhi-aware scoring logic, making it pedagogically accurate. Estimated effort is ~2-3 days.

## Acceptance Criteria

- [x] Audio-to-Type quiz has a tone 5 (neutral) button alongside existing tones 1–4
- [x] Neutral-tone questions generated from common particles: 吗, 了, 的, 着, 过, 们, 子 (and any other common neutral-tone syllables)
- [x] Sandhi-aware scoring: quiz accepts either dictionary pinyin (tone 3) or spoken pinyin (tone 2) for known sandhi rules (3-3→2-3)
- [x] QuizAttempt metadata extended to include `neutralToneTested` (boolean) and `sandhiQuestions` (count of sandhi-affected questions)
- [x] Existing tone 1–4 quiz functionality remains unchanged
- [x] Unit tests for sandhi-aware scoring logic
- [x] Storybook stories updated for the extended Audio-to-Type quiz UI
- [x] 0 lint errors across all changed files

## Business Rules

1. **Neutral Tone Button** — The tone 5 button already exists in `PinyinToneInput` via `TONE_BUTTONS_BASE` — no UI component change needed. The strategy simply needs to generate questions with `correctTone: 0` when a neutral-tone particle is used.
2. **Question Generation** — Neutral-tone questions are generated by selecting common particles and suffixes that are pronounced as neutral tone in natural speech. The question audio is generated with the neutral tone pronunciation.
3. **Sandhi-Aware Scoring** — Sandhi-aware scoring uses a new shared sandhi utility (`isSandhiAcceptable()`) that checks whether a user's tone answer is acceptable under known sandhi rules (currently: 3-3→2-3). Both frontend `evaluateAnswer()` and backend `submitAnswer()` use the same utility for consistent scoring.
4. **QuizAttempt Metadata** — QuizAttempt model is extended with an optional `metadata Json?` field via Prisma migration. The metadata object contains `{ neutralToneTested: boolean, sandhiQuestions: number }`. This enables analytics on sandhi practice coverage.
5. **Backward Compatibility** — Existing Audio-to-Type quiz sessions are unaffected. The tone 5 button only appears when the question involves a neutral-tone syllable. Sandhi-aware scoring is transparent to the user — they see correct regardless of which valid tone they type.
6. **Particle Whitelist** — Neutral-tone questions are generated from a whitelist of common particles: 吗, 了, 的, 着, 过, 们, 子. Only these syllables produce neutral-tone questions. Other tone-0 syllables are excluded to avoid non-particle neutral tones.
