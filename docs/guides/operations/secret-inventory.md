# Secrets & Resources — Canonical Inventory (Cross-Surface Ledger)

**Last Updated:** September 4, 2026
**Purpose:** The single source of truth for every secret, variable, and fixed resource identifier across **LOCAL → GITHUB → GCP → RAILWAY → NEON → UPSTASH → VERCEL**. Docs and runbooks link here; **never duplicate these tables elsewhere**.

> **No real secret value appears in this document.** Every value is either a **fixed identifier** (project/bucket/SA/service ids, public URLs — safe to write down) or marked **`{GENERATE_AT_RUNTIME}`** (minted at rotation time in the owning console — never committed, never pasted into a doc or chat).
>
> **How to use the ledger:** each row's **Logical name** is the join key. Find a name you met on any surface (say, `GCS_CREDENTIALS_RAW` on a Railway env) → that row tells you it is the `gcs-storage-service` SA key, which local file feeds it, who rotates it, and what code reads it — in one lookup. The audit behind this ledger (2026-09) found the confusion was not bad names but the absence of exactly this trace; nothing here renames anything. Backend-read names (`*_CREDENTIALS_RAW`, `JWT_SECRET`, …) are **frozen in code** — see §4 for how aliases handle that.

## 1. Store Map

**Backend-authoritative env surface** = `apps/backend/src/shared/config/index.ts` (the full env list + `validateConfig()` fail-fast on the **7 criticals**: `DATABASE_URL`, `JWT_SECRET`, `JWT_REFRESH_SECRET`, `GCS_BUCKET_NAME`, `GCS_CREDENTIALS_RAW`, `GOOGLE_TTS_CREDENTIALS_RAW`, `GEMINI_API_CREDENTIALS_RAW` — the last three validated via `client_email`). The ledger **aliases** instead of renaming: the Logical name is the stable human key; the runtime name is the code surface.

## 6. Refresh Cadence & Who Updates

This ledger is correct as of `last-verified` 2026-09-04. Refresh it **on every rotation and every release** (bump `last-verified` + `Last Updated` in the same commit, per the docs standards). Event-driven:

| Event                                                     | Who                                                        | Rows to touch                                                                                   |
| --------------------------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| New secret / env var added                                | Owner (GitHub/Railway) + backend engineer if code reads it | §2 (add row — find its Logical name; add alias/fan-out row in §4 if it maps to another surface) |
| SA rotated / key file regenerated                         | Owner                                                      | Group A rows (`*_CREDENTIALS_RAW` value source / present-files); **emails in §3 never change**  |
| Terraform output changed (e.g. Neon/Upstash URL)          | IaC                                                        | Group C rows (value source = `terraform output -raw <name>`)                                    |
| Env var added in backend code                             | Backend engineer                                           | Group F + the row's "Consumed by" (add `config/index.ts` / reader)                              |
| Workflow renamed / new consumer added                     | IaC / CI                                                   | §2 "Consumed by" on every affected row                                                          |
| Release cutover                                           | Owner + IaC                                                | Full §2–§5 sweep + bump both freshness stamps                                                   |
| GitHub-side rename executed (post-release, §4/§5 classes) | Owner                                                      | §4 alias table + §5, plus every doc referencing the old GH name (rename hygiene)                |

**How to verify the ledger is current (3 steps — mirrors how this audit was grounded):**

1. **Grep the workflows for the GitHub surface:** `grep -rniE "secrets\.|vars\." .github/workflows/` — the resulting name set must equal the GitHub column of §2 (Groups A, D, E). Consuming workflows as of 2026-09-03: `preview.yml`, `terraform-plan.yml`, `terraform-apply.yml`, `chromatic.yml` (`ci.yml` + `storybook-checks.yml` read none).
2. **Grep the backend for runtime names:** `grep -rniE "process\.env" apps/backend/src` — the name set must equal §2/Group F "Consumed by" + `config/index.ts`. Any new `process.env` read without a ledger row is a gap.
3. **Diff Terraform outputs:** `cd terraform && terraform init && terraform output` against Group C value sources + §3 fixed identifiers (remote state `gs://pinyin-pal-tfstate` — read-only, no apply).
