2. Service Map ¶

🌐 Vercel — Frontend Hosting

  • Static SPA (React + Vite build)
  • Auto-deploys on push to main
  • Preview deployments per PR
  • Domain: *.vercel.app
  • Output: apps/frontend/dist
  • Managed by: Terraform (vercel.tf)

🚂 Railway — Backend Hosting

  • Express API server
  • RAILPACK builder, health-checked
  • PR environments per branch
  • Envs: production + previews
  • No Terraform provider (click-ops)
  • Restart: ON_FAILURE, max 10 retries

🐘 Neon — PostgreSQL Database

  • Serverless PostgreSQL
  • Copy-on-Write branching for preview
  • Region: aws-ap-southeast-1
  • Managed by: Terraform (neon.tf)
  • History retention: 6h
  • Pooled + direct connection URIs

⚡ Upstash — Redis Cache

  • Serverless Redis (TLS via rediss://)
  • Primary region: ap-southeast-1
  • Eviction enabled, TTS cache TTL: 24h
  • Managed by: Terraform (upstash.tf)
  • Key prefix: mandarin:
  • Fail-open: no-op mode if unavailable

☁️ GCP — Cloud Storage + AI

  • Bucket: pinyin-pal-data (Singapore)
  • 3 service accounts (least-privilege):
  •   • tts-service — TTS API only
  •   • gemini-service — Gemini API only
  •   • gcs-storage-service — Bucket object admin
  • Public read for TTS audio (CORS: *)

🐙 GitHub — Source + CI/CD

  • Repository: coji831/mandarin-vite-react-ts
  • Branch: epic-20-mnemonic-stories
  • Secrets: NEON_API_KEY, RAILWAY_API_TOKEN, GCP_SA_KEY, VERCEL_TOKEN, UPSTASH_API_KEY, UPSTASH_EMAIL
  • Variables: NEON_PROJECT_ID, RAILWAY_PROJECT_ID, RAILWAY_BACKEND_SERVICE_ID
  • Workflows: preview, terraform-plan, terraform-apply, storybook-checks

15. Risk & Configuration Notes ¶

🔴 HIGH — Terraform State Storage: Currently stored locally (terraform.tfstate) in the repo. If the local state is lost or the CI runner is ephemeral, Terraform will see zero existing resources and try to recreate everything (GCS bucket, Neon DB, Upstash Redis). Mitigation: Configure a GCS backend for remote state storage.
🔴 HIGH — Railway IDs in GitHub Variables: RAILWAY_PROJECT_ID and RAILWAY_BACKEND_SERVICE_ID are hardcoded in GitHub repo variables. If the Railway project is recreated or the service is renamed, these become stale and preview environments will fail. No automated drift detection.
🟡 MEDIUM — GCS Upload Not in CI/CD: Content changes (new character files, updated manifests) require manual node scripts/upload-content-to-gcs.js execution. No GitHub Action syncs content to GCS on merge to main.
� RESOLVED (2026-09-03) — Vercel URL Sync: VITE_API_URL is Terraform-managed (vercel.tf, Production scope) — no Railway→Vercel integration dependency remains. It only changes when the pinned value in vercel.tf is edited and terraform apply is run.
🟡 MEDIUM — No State Locking: Terraform operations from multiple locations (local + CI) can conflict. No DynamoDB/S3 lock table configured.
🟢 OK — Cache Fail-Open: If Redis (Upstash) is unavailable, the CacheService gracefully falls back to no-op mode. TTS and content operations continue without caching.
