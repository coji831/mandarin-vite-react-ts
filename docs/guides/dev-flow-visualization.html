2. Frontend Flow — Detailed Pipeline

1 🔍 Gather Context Business need → User need → Web research. Read existing design docs, docs/design.md, component registry, and domain research in verification-artifacts/. Understand the user's mental model before designing UI.
→
2 ✏️ High-Level Design Wireframe / sketch (visual understanding). Map the user's flow step by step: what they see → what they think → what they do next. Establish preview/reward boundary. Check ui-composition.instructions.md & DESIGN.md tokens.
→
3 🧩 Component Breakdown Composition: atoms → molecules → organisms → page. Reuse check: component-registry.json + shared/components/. Hierarchy: parent → child, props interface. Impact: run codegraph_explore to find what depends on what you're changing.
→
4 📖 Detail Design Storybook for page-level or complex components (not every atom). Create .stories.tsx with MSW mocks. Cover all visual states (loading, empty, error, edge cases). Run npm run test-storybook.
→
5 🎭 Styling Priority order: ① global utility classes (.flex-center, .gap-sm, .w-full) → ② component CSS (BEM, scoped) → ③ shared component variants. CSS variables from globals.css only. No hardcoded colors/spacing/fonts. No global leak (no bare element selectors).
→
6 ⚛️ Logic State: useReducer, Context, Zustand stores (in stores/ dir). Hooks: usePhaseGate for feature gating. API: Create services/<name>Service.ts using apiClient from shared/api. Never call apiClient from components.
→
7 🧪 Testing By scope: ① Unit: changed code only (npm test). ② Integration: impacted scope (service + API). ③ E2E: cross-page or auth flows only (Playwright, when applicable). No brittle UI assertions — prefer role/text queries via RTL.
→
8 ✅ Audit Rules & conventions: CSS leaks, barrel files, API client rules, store placement (frontend-audit skill). Visual check: Storybook vs production side-by-side. Accessibility: ARIA labels, roles, keyboard support. Run frontend-pre-delivery-checklist.

3. Backend Flow — Detailed Pipeline

1 🏗️ Module Scaffold Create modules/<name>/ with api/, services/, repositories/, types/, container.ts. Choose CRUD, Feature Slices, or Clean Architecture template.
→
2 🗄️ Database Edit prisma/schema.prisma → npx prisma migrate dev → npx prisma generate. Never push to production. Use migration files.
→
3 💉 Container DI Create createXModule(deps) factory function. Register in root src/app/container.ts. Constructor injection at composition root.
→
4 🛣️ Routes Define routes with rate limiting. Register in src/app/routes.ts. Use shared constants from packages/shared-constants.
→
5 🔒 Validation Input validation at controller layer. Error responses in { error, code, message } format. "Failed to {action} {resource}" message convention.
→
6 ☁️ External Services GeminiService, CacheService, GCSClient — class pattern with constructor injection. Fail-open caching: Redis failures never block requests.
→
7 🧪 Tests Unit tests for service + repository. Integration tests for endpoints. Mock external services. vitest run src/modules/<module>/.
🏗️ Module Templates
CRUD: Controller → Service → Repository. Feature Slices: Mixed concerns, less overhead. Clean Arch: Complex business rules (quiz). No business logic in controllers.
modules/<name>/api/ /services/ /repositories/
💉 Dependency Injection
createXModule(deps) factory pattern. Direct instantiation at composition root (src/app/container.ts). Module depends on interfaces, not implementations.
createQuizModule({ db, cache, gemini })
🔒 Error Format
All errors: { error: "Failed to {action} {resource}", code: "LOAD_ERROR" }. Codes: VALIDATION_ERROR, NOT_FOUND, AUTH_ERROR, INTERNAL_ERROR.
"Failed to load review items"
📁 Repository Pattern
All DB access through repositories (abstracts Prisma). One method per query. Services never access Prisma directly. Repositories depend on PrismaClient.
repositories/UserRepository.ts
🔄 Layer Rules
API → Services/Use-Cases → Repositories → Infrastructure. Never reverse. Services call other services via module public API (index.ts). No HTTP knowledge in services.
Controller → Service → Repository
☁️ External Clients
Class pattern with constructor injection. GeminiService (AI), CacheService (Redis), GCSClient (Storage). Fail-open design — degrade, don't crash.
class GeminiService { constructor(private api: ...) }

4. Integration Points

📐 API Contracts
packages/shared-constants defines route patterns used by both FE and BE. packages/shared-types provides TypeScript interfaces shared across packages.
API_ROUTES.review → /api/v1/review
🔑 Auth Flow
JWT httpOnly cookies set by backend. apiClient interceptor handles token refresh. Refresh token rotation on re-auth. Frontend checks AuthContext for session state.
apiClient.interceptors.response → refresh token
🚦 Phase Gating
usePhaseGate() hook queries backend PhaseGate table. Frontend conditionally renders available sections. Locked tabs show indicators.
usePhaseGate(phase) → GET /api/v1/progress/phase-gates
⚠️ Error Flow
apiClient normalizes backend errors. Service layer handles and re-throws typed errors. Components render ErrorScreen or inline error with retry. Three states: loading, error, success.
apiClient → service → hook → ErrorScreen
📦 Shared Packages
shared-constants: route paths, HSK levels, regex patterns. shared-types: TypeScript interfaces. Changes must be synced across FE + BE.
packages/shared-constants/ src/ packages/shared-types/ src/
⚡ Vite Dev Proxy
In dev, Vite proxies /api/* to localhost:3001. In prod, frontend (Vercel) calls backend (Railway) directly via API routes.
npm run dev (FE :5173) → proxy → npm run start-backend (BE :3001)

6. Story-Level Workflow

Sequential steps when implementing a story. From project-workflow.instructions.md.

1
📖 Review Requirements
Open story BR + epic BR README. Confirm AC clarity. Note ambiguous items in "Questions / Clarifications" subsection. Read corresponding implementation docs.
2
🧠 Design Thinking & User Flow
Read research/design docs. Map user flow: What do they see → think → want to do? Establish preview/reward boundary. Check source for every design decision. Apply WAGC, content density, clarity, cognitive load principles.
3
📋 Plan Changes
Read AGENTS.md for behavior rules. Identify impacted feature folders. Check design doc + docs/architecture.md for conflicts. Prepare file header summaries for new public APIs.
4
💻 Implement Code
Create/update components, hooks, reducers, types. Domain-prefixed action types. Immutable updates. Normalized collections. Scope tightly bound to story AC. Defer extras to follow-up story.
5
🧪 Write Tests
Unit/component tests: happy path + ≥1 edge case from AC. Reducer/action/selector isolation tests. RTL role/text queries. Avoid brittle assertions. Mock external services.
6
🏃 Run Locally
npm run dev (FE) + npm run start-backend (BE if API touched). Manual sanity check. Exercise UI path for story. Capture discrepancies against AC.
7
👁️ Visual Verification
Start Storybook + dev server. Wait for full load. Screenshot side-by-side. Compare layout, spacing, colors, structure. Fix mismatches. Log findings in verification-artifacts/. Run npm run test-storybook.
8
📝 Update Documentation
Record decisions, data shape changes, performance notes in story implementation doc. Add "Technical Challenges & Solutions" section. Update Last Update dates. Cross-link BR ↔ implementation ↔ stories.
9
🚦 Pre-Commit Gate
Run ALL quality gates: npm run format → npm run build → npm run test:full → npm run test-storybook → npm run lint (0 errors). Design audit. Cross-doc alignment check. No TODO/FIXME/commented-out code.
10
✅ Commit
Conventional Commit format: <type>(story-<epic>-<story>): <summary>. BR + implementation doc updates in same commit. Reference PR number in both docs. Close epic: update Status + Last Update, verify all AC done.

Pre-Implementation Investigation Checklist

🔍 Pattern Investigation
Read target feature directory for existing architecture patterns. Check if reusable pattern exists. Never build standalone when reusable pattern exists.
📁 Project Structure Verification
Verify file placement: features/ for components, pages/practices/ for quiz pages, stores/ for state. Never place in unrelated directories.
🛣️ Routing Convention Check
Examine route files + shared/constants/paths.ts. Check query params vs path segments patterns. Never create new patterns when established convention exists.
💾 Data Source Audit
Determine data source: backend API, content files, or generated. Check if backend endpoints exist. Never hardcode data when backend API exists.
